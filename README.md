# IMAPdedup
*A duplicate email message remover*

**Please note that these instructions -- the installation instructions in particular -- have changed since version 1.1.**

IMAPdedup is a command-line utility that looks for duplicate messages in a set of IMAP mailboxes and tidies up all but the first copy of any duplicates found.

To be more exact, it *marks* the second and later occurrences of a message as 'deleted' on the server. Exactly what that does in your environment will depend on your mail server and your mail client.

Some mail clients will let you still view such messages *in situ*, so you can take a look at what's happened before 'compacting' the mailbox. Sometimes deleted messages appear in a 'Trash' folder. Sometimes they are hidden and can be displayed and un-deleted if wanted, until they are purged.

Whatever your system does, you will usually have the option to see what has been deleted, and to recover it if needed, using your email program, after running this script. (If your server purges the deleted messages automatically, you may be able to prevent this with the `--no-close` option.) There is also a 'dry-run' option (`-n`), so you can check what might happen before doing anything scary.

## How it works

By default, IMAPdedup will simply look for messages with a duplicate `Message-ID` header. This is a string generated by email systems that should normally be unique for any given message, so unless you've got some rather unusual mailboxes, it's a pretty safe choice. (Note that Gmail, for example, *does* sometimes have some unusual mailboxes.)

* **Header Checksum (`-c`):** If you have messages *without* a Message-ID header, or you don't trust it, there's an option (`-c`) to use a combined checksum of the `From`, `To`, `Subject`, `Date`, `Cc`, `Bcc`, and `Content-Type` headers instead.
* **Include Message-ID in Checksum (`-m`):** Add `-m` alongside `-c` to include the `Message-ID` (if present) into the multi-header checksum. This is highly recommended for safety.
* **Smart Body & Attachment Verification (`--check-body`):** Enabled by default! When header hashes match, IMAPdedup fetches and verifies that the message body and all attachments are identical before flagging a duplicate. It decodes plain text, normalizes line endings and whitespace, and calculates cryptographic SHA-256 hashes over all attachment payloads. (If you want to skip body comparison for maximum speed, pass `--no-check-body`.)
* **Immutable IMAP UIDs:** IMAPdedup indexes messages using permanent IMAP UIDs (RFC 3501) rather than transient sequence numbers, guaranteeing that new incoming emails or shifting message indices will never cause the wrong message to be targeted.
* **Checkpointing & Auto-Resumption:** Tracks progress in chunks of 100 UIDs. If a connection drops, timeout occurs, or the server throttles, IMAPdedup reconnects and automatically resumes from the last scanned UID, without starting over from message 1.
* **Server Throttling Backoff:** Automatically detects Microsoft Exchange / Office 365 rate-limiting (`Suggested Backoff Time`), waits the suggested delay, reconnects, and resumes cleanly.

## Installation

You can install IMAPdedup using pip:

    pip install imapdedup

This will install the script, and you can then just run it from the command line as `imapdedup`. In the examples below, we'll assume you've done that.

### Alternative installations

Some environments may require you to use `pip3` instead of `pip`. And some may not let you install packages globally. In that case, you can use the `--user` option to install it in your home directory:

    pip install --user imapdedup

Note that IMAPdedup doesn't *need* any installation process, however, and doesn't have any external dependencies beyond Python standard libraries. You only need Python 3 and can then just download and run the `imapdedup.py` file which you can find in `src/imapdedup`. The command you would run would then be something like:

    python3 imapdedup.py ...

If you use the [uv](https://docs.astral.sh/uv/) tool, you can run:

    uvx imapdedup

or from the source repository:

    uv run imapdedup ...

### Using Docker

To run IMAPdedup in a Docker container, you can use the following commands:
First, build the image:

    docker build -t imapdedup .

Then you can run the container with the following command:

    docker run --rm -it imapdedup --help

See _[Simple-use](#simple-use)_ for more information on how to use IMAPdedup.

## Trying it out

If you want to experiment, create a new folder on your mail server, and copy some messages into it from your inbox. Then copy some of them in a second time. And maybe a third. That should give you a safe place to play!

## Simple use

You can list the full syntax by running:

    imapdedup -h

The key options are described below. You will of course need the address of your IMAP email server, and your username on that server.

Try starting with something harmless like:

    imapdedup -s imap.myisp.com -u myuserid -x -l

which prompts you for your password and then lists the mailboxes on the server. You can then use the mailbox names it returns when running other commands. (The `-x` option specifies that the connection should use SSL, which is generally the case nowadays. If this doesn't work, you can leave it out, but you should probably also complain to your email provider because they aren't providing sufficient security!)

It's worth getting this list at least once because different mail servers structure their folders differently. One of mine thinks of all the folders as being 'within' the inbox, for example, so they're called things like 'INBOX.Drafts', 'INBOX.Sent', and those are the names I need to use when talking to the server.

Once you know your folder names, you can run a dry run preview:

    imapdedup -s imap.myisp.com -u myuserid -x -c -m -n INBOX.Test

and the script will tell you what it would do to your *INBOX.Test* folder. If your folder name contains spaces, put it in quotes:

    imapdedup -s imap.myisp.com -u myuserid -x -c -m -n "My Important Messages"

The `-n` option tells IMAPdedup that this is a 'dry run': it stops it from *actually making* any changes. When you're ready to delete duplicates, remove `-n`:

    imapdedup -s imap.myisp.com -u myuserid -x -c -m INBOX.Test

### Additional Options

* `-v` / `--verbose`: Verbose output showing batch progress and headers.
* `-S` / `--show`: Print subject, from, date, and content-type for each duplicate found.
* `-d` / `--delete`: Ask the server to expunge (permanently purge) marked duplicate messages immediately upon completion.
* `-y <folder>` / `--copy <folder>`: Copy duplicate messages to the specified mailbox before marking them for deletion from their current location.
* `-t <tag>` / `--only-tag <tag>`: Tag duplicates with a custom IMAP keyword instead of marking them with `\Deleted`.
* `-r` / `--recursive`: Recursively process all child mailboxes under the specified parent mailbox.
* `-R` / `--reverse`: Walk through folders in reverse order.
* `-b <date>` / `--sentbefore <date>`: Only process messages sent before a given date (e.g. `1-Feb-2020`).
* `--no-check-body`: Disable body and attachment comparison, relying purely on header checksums.

## OAuth2 Modern Authentication

IMAPdedup supports modern OAuth2 (`XOAUTH2`) authentication for Office 365, Google Workspace / Gmail, and other OAuth2 providers:

    imapdedup -u user@example.com -o -c -m "INBOX"

When `-o` / `--oauth2` is specified:
* IMAPdedup automatically looks for OAuth2 token files (such as those generated by `oauth2_imap`) in standard token directories.
* You can specify a custom token file with `--token-file /path/to/tokens.txt`.
* If a token expires during a long multi-hour run, IMAPdedup automatically invokes the token refresh script and retries authentication seamlessly.

### Custom Domain Server Mapping (`--server-map`)

When using OAuth2, IMAPdedup can infer server hostnames for standard domains (`gmail.com`, `outlook.com`, `office365.com`, etc.). For custom hosted domains, you can either provide `-s <server>` or map domains using `--server-map`:

    imapdedup -u user@customdomain.org --server-map customdomain.org=outlook.office365.com -o -c -m "INBOX"

Multiple `--server-map` flags can be passed for multi-domain setups.

## Specifying the password

If not using OAuth2, you have several ways to provide passwords securely:

* **Environment Variable:** Set `IMAPDEDUP_PASSWORD`.
* **System Keyring (`-K`):** Use the system keyring via Python's `keyring` library:
  ```bash
  pip install keyring
  imapdedup -s imap.example.com -u myuserid -x -K
  ```
* **Interactive Prompt:** If no password flag or environment variable is set, IMAPdedup will securely prompt you for one.

## Authenticating as an admin user

Some IMAP servers allow an admin user to login and perform actions on behalf of another user via `AUTHENTICATE PLAIN`. The `-a` option specifies the admin username:

    imapdedup -s imap.example.com -u user_to_dedup -a admin_user -w admin_password -x "INBOX"

## Checking ALL of your mailboxes

To deduplicate across all folders, query the folder list and pipe it to IMAPdedup:

    # 1. Obtain the clean list of mailboxes
    imapdedup -x -s servername -u username -w password -l > folders.txt

    # 2. Process all folders (dry run first)
    cat folders.txt | sed 's/^\(.*\)$/"\1"/' | xargs imapdedup -x -s servername -u username -w password -c -m -n

    # 3. Perform deduplication & expunge
    cat folders.txt | sed 's/^\(.*\)$/"\1"/' | xargs imapdedup -x -s servername -u username -w password -c -m -d

## Accessing IMAP via a local process

The `-P` option allows you to access mailboxes via stdin/stdout to a subprocess (e.g. Dovecot):

    imapdedup -P "/usr/lib/dovecot/imap -o mail_location=maildir:~/.mbsync/mails" -u username "INBOX"
